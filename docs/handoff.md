# 引継ぎメモ（handoff）

セッションをまたぐ**揮発的な引継ぎメモ**。**このファイルは毎回上書き**（最新1件だけを保持する）。
過去の失敗の蓄積は `docs/failures.md`（append-only・消さない）を見る。

## ①今回実施

既存プロダクトを持ち込んだセッションで摩擦が多発した実例をもとに、`AGENTS.md` を改定した。
原因は「コピー先で読まれるのに、リポジトリの来歴と目的が本文に書かれていた」こと。

- **削除**：「このリポジトリの位置づけ：テンプレ専用」節（運用フロー1〜2を含む）。コピーは原本と
  同一ファイルなので、製品を作る場所で「ここで作るな」と読まれ、セッション冒頭の復唱と
  「どれで進めますか」というメニュー化を招いていた。
- **新設**：「このプロジェクト」欄（スタック／チェックコマンド／引継ぎ記録の場所）、
  「セッション開始時の判定」（`git branch -a` で所在確認、同梱サンプルはコードに数えない、
  プロダクトのあるブランチで作業、3分岐）、「取り込み」7手順（無確認実行＋事後報告）、
  「確認せずに進めること／必ず確認すること」。
- **書き換え**：pnpm 決め打ちの Testing instructions →「このプロジェクトのチェックコマンド」参照に。
  鉄板構成と初期化フローは「コードが無い場合のみ／既存には適用しない」とスコープを明示。
- **周辺の追随**：`presets/_TEMPLATE.md`（宙吊り参照の解消・モノレポ用途に限定）、
  `checkin-checkout/SKILL.md`（判定を先に実行／引継ぎ記録の場所に読み替え／土台ブランチの修正）、
  `README.md`（人間向けの「コピーして始める」導線をここへ移設）。

検証：サブエージェント2体（摩擦の残存／安全性の後退）に敵対検証させ、初稿の欠陥を修正した。
特に `ci.yml` の集約ゲート job 名 `ci-green` は `scripts/setup.sh` の必須チェック名と結合しており、
CI 書き換え時の維持を明記した。型・Lint・テストは緑（32 tests passed）。

## ②今回トラブル

初稿に、このリポジトリ自身を「取り込み」対象と誤判定して同梱サンプルを自動削除する欠陥があった。
敵対検証で発覚し、確定案では解消済み（詳細と教訓は `docs/failures.md`）。
